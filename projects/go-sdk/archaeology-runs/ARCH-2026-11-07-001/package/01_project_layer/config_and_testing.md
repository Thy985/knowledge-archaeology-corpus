# 01.4 Configuration & Testing · 配置面与验证面

## 1. 服务端 HTTP 配置（`StreamableHTTPOptions`，`streamable.go:147`）

| 配置 | 默认 | 语义 |
|---|---|---|
| `Stateless` | false | true = 不读/不设 `Mcp-Session-Id`，GET/DELETE 405，每请求临时会话 |
| `JSONResponse` | false | 用 `application/json` 代替 `text/event-stream` |
| `EventStore` | nil | 启用断点重放；nil 则无法 replay |
| `SessionTimeout` | 0 | 有状态会话空闲超时；0 = 永不超时 |
| `DisableLocalhostProtection` | false | 关闭 DNS rebinding 防护（loopback 上 Host 必须 loopback） |
| `CrossOriginProtection` | nil | 已标记 Deprecated，建议外层 middleware |
| `MaxRequestBodyBytes` | 4 MiB | 读取期强制；负数 = 关闭（不推荐） |
| `StreamKeepAlive` | 30s | SSE 无字节时写注释行；负数关闭 |
| `PropagateRequestCancellation` | false | 仅 ≥2026-07-28：HTTP 请求取消传导到 handler |
| `OnRequestSummary` | nil | 观测脱敏摘要；batch 不触发 |
| `Logger` | nil | 结构日志 |

## 2. 服务端核心配置（`ServerOptions`，`server.go:93`）

| 配置 | 默认 | 语义 |
|---|---|---|
| `SupportedProtocolVersions` | 空 = 全部 5 个 | **只能收窄，不能拓宽**；新协议被排除版本返回 `CodeUnsupportedProtocolVersion`；旧握手永不拒绝，返回可协商版本让客户端自行断开 |
| `GetSessionID` | 随机 UUID | 返回空串 = 不设置 session header；Stateless 模式不咨询 |
| `KeepAlive` / `KeepAliveFailureThreshold` | 0 / 0 | 定期 ping；阈值 0 或 1 = 首次失败即关闭 |
| `Capabilities` | nil = `{"logging":{}}`（历史原因） | 非 nil 覆盖推断；`&ServerCapabilities{}` 关闭 logging |
| `InitializedHandler` | nil | 收到 initialized 通知 |
| `PageSize` | `DefaultPageSize` | 列表分页 |
| `SchemaCache` | nil | 无状态部署每请求新建 Server 时缓存 JSON Schema |
| `SetCacheable` | nil | 控制 ttlMs/cacheScope |

## 3. 客户端配置（`ClientOptions` / `ClientSessionOptions`）

- `ClientOptions.Capabilities` 默认 `{"roots":{"listChanged":true}}`（v1.0.0 历史默认，不可改）。
- `Roots` 字段被 `RootsV2` 覆盖（issue #607）。
- `ClientSessionOptions.ProtocolVersion` 为空则使用 latest（2026-07-28）。
- `KeepAlive>0` → 定期 ping。

## 4. 兼容开关（`MCPGODEBUG`）

`docs/mcpgodebug.md` 记录按版本累积的开关，用于"临时恢复旧行为"：

| 版本 | 代表开关 | 作用 |
|---|---|---|
| 1.9.0 | `structuredcontentfloat64`、`disablepromptargsvalidation`、`nopreinitinvalidrequest`、`fatalnewprotocolerrors`、`followallredirects` | 新行为/严格化 |
| 1.8.0 | `plaintextstatefulrejection`、`blockingcancelnotify` | 有状态明文拒绝、取消通知阻塞 |
| 1.7.0 | `allowsessionsinstateless`、`nowrapinvalidparams`、`noprotocolerrorbody` | 无状态兼容会话、错误体格式 |
| 1.6.x | `enableoriginverification`、`jsonescaping` | 跨域校验、JSON 转义 |
| 1.4.x | `disablecrossoriginprotection` | 关闭跨域保护 |

> 这是一套**按版本号累积的运行时兼容层**：默认采用新行为，旧行为需显式开启。它不是"配置项"，而是"发布节奏的逃生舱"。

## 7. 配置面判断

1. **默认值偏安全**：body 4 MiB、keepalive 30s、localhost 防护默认开、token 缺 expiration 默认拒。
2. **兼容开关是"负向配置"**：正常路径不提旧行为，只有显式 `MCPGODEBUG` 才回退。
3. **一致性测试存在"负向清单"**：不是所有 conformance 用例都通过，缺口被写进 baseline。
