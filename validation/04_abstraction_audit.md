# 04 · 五层抽象审计（Five-Layer Abstraction Audit）

> 判据：抽象层级提升的标准是**解释范围是否真的扩大**，不是"文字是否更抽象"。
> L1 事实 → L2 解释 Why（禁止同义反复）→ L3 重复结构（≥2 独立实例）→ L4 认知模型（解释多个机制，否则 L4_OVERREACH）→ L5 方法论（需跨上下文适用性 + 已知例外）。

---

## 逐层审计规则回顾

| 层级 | 判据 | 判定 |
|------|------|------|
| L1 | 存在明确可验证的工程事实 | 无事实 = 无效 |
| L2 | 解释 Why 而非复述 What | 同义反复 = L2_INVALID_TAUTOLOGICAL |
| L3 | ≥2 独立实例证明重复结构 | 单实例 = Observed Structure，不得升级为 Pattern |
| L4 | 认知模型解释多个不同机制 | 只解释一个模块 = L4_OVERREACH |
| L5 | 项目证据 + 重复结构 + 跨上下文适用性 + 已知例外 | 无跨上下文 = 项目局部经验，不得升 L5 |

---

## KO-01 · L4 判定

- **L1 基础**：存在（Approval Gate 三态、沙箱选择、Guardian 独立 session）✅ 但 L1 有事实错误（approval_policy 实为四态）——事实错误不影响层级判定，但**必须先修正**。
- **L2 是否同义反复**：否。解释了"为什么分离"（Agent 判断不可靠 → 独立 Gate 链），非复述。✅
- **L3 重复结构**：Approval Gate 在工具执行/Guardian 审批/网络访问多处出现（≥2 独立实例）。✅
- **L4 解释范围**：Intelligence ≠ Authority 解释了工具执行 Gate、Guardian 审批、网络代理三个机制，且与 exec_policy（命令级审批）相关。解释范围确实扩大。**VALID**。
- **L5 判定**：L5 方法论 5 条（受控接口/证明执行分离/按可逆性×影响授权/可审计/降级触发额外审批）——大部分可跨项目适用，但 **L5.5"降级必须触发额外审批"被反例削弱**（BypassSandboxFirstAttempt 首次即无沙箱，非"降级后额外审批"）。L5 需条件化。

**结论**：L4 VALID；L5 需条件化（标注 bypass 例外）。

## KO-02 · L4 判定

- **L1**：存在（transcript 限流/结构化评估/超时/熔断/延迟确认）✅
- **L2**：解释了 Why（AI 审批也是 AI，可能错 → 需证据链）✅ 非同义反复。
- **L3**：证据生产链 = TDD red→green / 可复现门槛 / CI 门禁的同类（≥2 对照实例成立）。✅
- **L4**：声明≠证据解释了 transcript 限流、结构化输出、超时、熔断器、延迟确认 5 个机制。解释范围扩大。**VALID**。
- **L5**：5 条方法论可跨项目适用（自动审批绑定审计记录/未通过不承认批准/分级证据强度/熔断/延迟确认）。✅ 唯一例外：延迟确认只适用于可取消操作（如网络代理），不可取消操作不适用——需在 L5.5 补"仅限可取消动作"。

**结论**：L4 VALID；L5 补充"延迟确认限可取消动作"边界。

## KO-03 · 抽象层级审查（重点）

- **L1**：存在（CODEX_SANDBOX* 环境变量由运行时设置、内部只读、用于测试跳过）✅
- **L2**：解释了 Why 吗？AGENTS.md 层面解释了"为什么不能改"（运行时约束），但 KO-03 的 L2 把解释引向"递归矛盾"——**这一步就是过度演绎的起点**。实际机制是"环境隐式契约"（外部运行时告知代码当前约束），不是"自举递归"。
- **L3**：同类对照（编译器 stage0 / VM host-guest / Docker-in-Docker）描述的是**真正的结构递归**。codex 的 CODEX_SANDBOX* 是**测试环境检测**，不具备同类递归结构。**无 ≥2 独立实例**支撑"递归逃逸阀"模式 → 按规则应判为 **Observed Structure（环境隐式契约）**，而非 Pattern（递归逃逸阀）。
- **L4**："被管理者同时是管理者的宿主，必须存在显式逃逸阀" —— 该认知模型对 codex 而言解释范围**未扩大**（只解释了测试跳过一个机制，且把较弱的机制套进较强的模型）。**OVERREACH**。
- **L5**：基于递归模型的方法论（识别递归点/提供逃逸阀）对 codex 证据不足，属于**在过度抽象上构建的方法论**。

**结论**：**DOWNGRADED**。真实层级为 L2（环境隐式契约的工程知识），可考虑弱 L3（外部设置/内部只读/文档化治理的信号模式），但"递归矛盾/逃逸阀"应移入 Candidates 待跨项目验证。

## KO-04 · L3 判定

- **L1**：存在（三策略从 PermissionProfile 派生、三字段同步、环境级覆盖）✅
- **L2**：解释了 Why（多维度独立配置会冲突 → SSOT）✅
- **L3**：SSOT 模式有明确同类对照（DB schema/declarative config/React state），且 codex 内三策略维度即 ≥2 实例。✅
- **L4**：SSOT + 纯函数派生解释范围确实扩大（不限于沙箱策略，可用于任何多维度约束系统）。虽标 L3，L4 模型也在合理范围。**VALID**。
- **L5**：方法论可跨项目适用。✅

**结论**：L3 VALID（L4 模型合理但保留 L3 标注恰当——证据强度足够支撑 L3-L4）。

## KO-05 · L4 判定

- **L1**：存在（Guardian fail closed / 升级条件 / 附件网络策略 / 多 Agent 超限 / 熔断器）✅ 但升级条件列举不完整（缺 network_approval_context / should_bypass_approval / owner_network_policy）。
- **L2**：解释了 Why（误放代价 >> 误拒代价）✅
- **L3**：fail closed 有明确同类（防火墙/权限默认拒绝/HTTPS/DB 远程拒绝），codex 内 5 实例。✅
- **L4**："fail closed 是对智能不确定性的结构性回应" 解释范围确实扩大（5 个机制指向同一原则）。**VALID**。
- **L5**：方法论可跨项目适用。但需加边界：**fail closed 是默认而非绝对**，用户显式白名单（Never/ExecPolicy Allow）是已知例外（L5.4 已提及，需强化）。

**结论**：L4 VALID；L5 强化"默认路径"边界。

## KO-06 · L3 判定

- **L1**：存在（crate bloated 自述、resist adding、push back、Session 20+ 字段）✅
- **L2**：解释了 Why（路径依赖正反馈）✅
- **L3**：模块边界治理有同类（微服务拆分/monorepo 约束/内核子系统），crate 级治理成立。✅ 但**证据覆盖不完整**：未纳入模块级（500/800 LoC）、变更级（800/500 行）、API surface 三个同族治理。若纳入，可升为 L4"多层级膨胀治理模型"；否则保持 L3 但标注局部。
- **L5**：方法论可跨项目适用。✅

**结论**：L3 VALID；建议扩展覆盖为"多层级膨胀治理体系"（L3-L4）。

## KO-07 · L4 判定

- **L1**：存在（4 处五段式实例）✅
- **L2**：解释了 Why（每段独立关注点可独立审计/升级/失败）✅
- **L3**：4 处独立实例成立（≥2）。✅
- **L4**："可审计代理系统的架构指纹" 解释范围确实扩大（工具执行/Guardian/网络/Session 初始化 4 机制）。**VALID**。但需 epistemic nuance：4 处**同源设计**（同一架构团队刻意设计），非自然涌现——"指纹"是设计签名，跨项目是否重现未验证。
- **L5**：方法论可跨项目适用（显式划分五段/独立失败模式/记录段完整）。✅

**结论**：L4 VALID（补充"同源设计"标注；跨项目重现性待验证）。
